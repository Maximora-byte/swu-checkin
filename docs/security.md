# 安全模型

## 威胁边界

项目处理校园账号、认证 session 和学校返回的宿舍/任务数据。只有身份、请假、任务与 payload 可以安全校验时才进入提交，只有回读确认已签到才报告提交成功；HTTP 200 或业务成功标志本身不够。

本工具不测量实际 GPS。现有提交 payload 使用学校宿舍坐标，且包含固定的 GPS/范围字段，不能证明本人当前在寝。仅应在申报真实且符合学校规则时正式提交；桌面自动模式默认关闭，启用前明确告知并单独确认，不满足条件时应提前停用。项目不扩展定位绕过、反检测或认证绕过，不新增第三方账号托管服务，也不对未知响应结构做猜测式兼容。

## 凭据

- 本地 CLI 通过环境变量或 `input()` / `getpass()` 获取凭据，不保存密码；`setup` 始终交互输入
- GitHub Actions 使用 Repository Secrets
- Windows 安装脚本和桌面版分别使用当前用户、当前机器绑定的 DPAPI 密文；不得将密文复制到其他账号/机器后期待可用
- macOS 桌面仅在显式保存时使用系统文件型钥匙串；读取/清除也由按钮触发，token 仅在进程内存，失败不回退明文文件。完整边界见 [macOS 指南](macos-desktop.md)
- Android 默认不保存账号；显式勾选后才使用 Android Keystore AES-256-GCM 加密账号文件，读取/清除由按钮触发，token 仅在进程内存。密文位于 `noBackupFilesDir`，应用禁止备份和数据迁移；详细行为见 [Android 指南](android-client.md)
- systemd 使用 `/etc/swu-checkin/credentials.env`，要求 `0600 root:root`
- 凭据、验证码、token、ticket、OAuth state/code 不得进入 Git、Issue、PR、截图或日志

DPAPI、Keychain 和 Keystore 保护持久化秘密；它们不能证明设备可信，也不消除运行时内存里的账号、密码或 token。Android 密钥不以文件形式导出，但当前没有要求生物识别解锁、硬件支持声明或设备完整性证明；损坏密文、丢失密钥和验证失败均停止读取，不回退明文。POSIX CLI token cache 使用文件权限保护，内容并未加密。不要让不可信程序访问运行账号或状态目录。

## OAuth/CAS

登录链从可信 SWU HTTPS 响应逐跳发现 redirect、state、form 和 hidden input，并校验主机、协议、端口、路径和参数唯一性。未知主机、异常端口、歧义字段和不允许的路径失败时，不回退到猜测 URL。极窄的学校旧式 IDM HTTP 地址只作为服务端数据校验，实际请求升级为 HTTPS；不是允许任意 HTTP 降级。

业务接口和 token exchange 也禁用自动重定向并拒绝 3xx，避免自定义认证头或签到表单被转发到非预期地址。精确规则及受限的 412/404 兼容见 [OAuth 登录发现说明](oauth-login-discovery.md)。

## TokenStore 与只读诊断

- CLI/Windows 文件 cache 只保存验证过的 token、账号绑定及格式元数据，不保存密码；缓存命中不代表密码已重新验证。macOS/Android 前端显式注入内存 TokenStore，不能回退到 POSIX 明文缓存
- POSIX 文件原子写入并使用 `0600`；Windows 内容使用 DPAPI；不安全或不可读的缓存不会被当成有效 session
- 复用 cached token 前仍请求身份接口，要求返回学号、缓存绑定学号和请求账号一致
- 初始身份校验明确拒绝 token 或账号绑定不一致时，清理对应 cache 并重新认证；没有 cache 时也会认证并尝试保存验证结果
- 只有来自 cache 的 session 在**提交前业务读取阶段**收到明确 HTTP 401/403 或顶层业务 `code` 401/403 时，正式流程才清 cache 并 fresh-auth 恢复一次；新 session 再失效则停止
- schema、JSON、超时、网络错误和未知业务码不会被误判为会话失效，也不会仅因此清 cache
- `doctor` 和 `setup` fresh-auth 并检查只读接口，不读写 TokenStore、不写运行状态
- `probe` 不提交签到、不写正式运行状态、不获取正式运行锁；它可因初始身份校验替换 cache，但不会恢复业务读取阶段才失效的 cached session

“只读”是业务边界，不代表零网络请求、零 HTTP POST 或所有本地文件均不可变。认证、宿舍查询和任务查询本身可能用 POST。桌面定时只读检测还会保存非敏感的最近定时结果；与正式 `status.json` 分开。

前端只读诊断与 CLI `doctor` 的缓存策略也有区别：macOS 桌面诊断明确禁用缓存读取/写入；Android 查询与诊断允许复用并更新当前进程内的验证 token，仍不会提交签到或写正式状态文件。Android 再次运行时检测到账号/密码变化会清除旧会话，不能仅根据已有 pending UI 跳过提交前的身份、请假与任务复查。

## 提交、重试和回查

正式流程依次验证身份、读取请假与今日任务；请假中、无任务、已签到时提前结束。只有确认待签到后才继续学生/宿舍校验并构造 payload。请假读取有分页上限；不能确认完整性时 fail closed，不把不完整结果猜成“无请假”。

外层重试只用于无任务、被分类为认证网络错误的失败和提交前已识别的瞬时传输失败。凭据拒绝、最终验证码失败、结构错误、未知业务响应或不能恢复的 session 失效不盲目重试。验证码内部重试和只读回查不属于重复提交。

同一次正式业务调用最多发出一次**签到提交 POST**。如果提交发生 timeout、连接中断、HTTP 错误等请求异常，或取得可解析的响应，客户端最多只读回查 4 次；只有确认已签到才返回成功。即使提交正文表示业务成功，未确认远端状态也返回失败。提交解析/结构异常可能直接失败，并非所有失败都保证回查。

这些提交结果都不会导致 outer retry 再发签到表单，也不会因提交/回查中的 401/403 重新登录并再次提交。新的独立手动调用或下一次定时触发仍是新的调用，不是服务器端幂等保证；不确定时先诊断，勿连续重跑。

## 并发

正式 CLI 和桌面后端共同通过 `formal_execution` 使用跨进程非阻塞锁：

- POSIX 使用 `fcntl.flock(LOCK_EX | LOCK_NB)`；Windows 使用 `msvcrt.locking(..., LK_NBLCK, 1)`
- CLI 在读取凭据前获取锁，并保持到执行和状态记录结束；桌面锁覆盖正式业务与状态记录
- 锁文件不保存 PID、账号、token、payload 或业务状态；文件存在不代表锁被持有
- 同一锁域中的第二个正式 CLI 本地跳过，退出 `0`，只向 stderr 输出固定消息；即使 `--json` 也不输出结果文档、不写状态
- 桌面锁冲突不会提交，但不会沿用 CLI 的 exit-0/no-op 呈现；桌面定时入口异常退出 `1`
- `probe`、`doctor`、`setup`、`status` 不获取正式锁；直接调用 Python 业务 API 也不自动加锁

锁只协调同一机器、同一路径的协作进程，不能阻止学校 App、其他机器或不同锁路径同时操作。不得删除正在使用的锁文件来“解锁”；默认路径与覆盖方式见 [CLI 参考](cli-reference.md)。

Android 在应用私有目录使用独立 RuntimeLock 串行化手动操作，并有 UI busy 状态与实际提交入口的确认/取消校验；该锁域不与电脑 CLI、桌面软件或其他手机共享。它不是远端幂等保证，不能用来允许同一账号并行调度多端正式提交。

## 状态与日志

`status.json` 只记录上海日期、最近最多 10 次正式调用的时间/状态码/固定消息及聚合成功标记；它与 CLI schema v1 JSON 是不同格式，也不是学校实时状态。systemd 通过专用用户和受限目录保护它。状态保存失败不应被当成远端失败或再次提交理由。

业务日志只允许固定异常分类、已审查的阶段名称或安全结构信息。阶段包括 `auth`、`token_validation`、`leave`、`transition`、`student_profile`、`dormitory`、`submit`、`confirm`。传输失败可记录“请求超时”“连接异常”或 HTTP 状态；业务响应只记录“业务码已返回”“显式失败标志”等固定分类。未知 `code/status` 即使看似短数字或普通英文，也不记录原值、哈希、前后缀或部分遮罩，因为它可能是认证材料或账号标识。

普通 CLI 的业务诊断通常在 stdout；`--json` 才将其重定向到 stderr，保留 stdout 给业务结果。桌面界面只接受封闭错误枚举对应的固定消息；未分类异常显示固定通用提示，不显示 traceback 或任意异常文本。报告问题时只附版本、阶段、类型与脱敏字段结构，不附原始 body/message、完整回调 URL、宿舍地址、房间、坐标或认证材料。

## Windows 桌面版

- 无参数启动只打开界面，本地恢复配置不连接学校；`--self-test` 使用合成数据验证离线依赖，`--scheduled` 才执行已保存且启用的模式
- 只有显式“保存账号”才持久化密码；任务参数只有 `--scheduled`，不携带账号/token；启用模式前会重新检查已保存账号
- `SWUDK_PROBE_ONLY=1` 同样阻止桌面正式签到；手动提交需确认本人在寝，自动签到需单独确认后才启用
- 当前桌面任务为 `SWUCheckin-Desktop`；启用前检测旧 `SWUCheckin-Daily`，存在时阻止建立第二套定时，不自动删除旧任务
- 任务查询通过根目录的 Task Scheduler COM 查询区分存在/明确不存在；访问拒绝、服务故障、超时或无法解释的输出均视为未知，不能当成已关闭
- 创建/删除任务后会重新查询并协调本地配置；不能确认最终状态时，GUI 显示“状态未知”并禁用定时控件，要求检查任务计划程序后重开应用。未知不保证任务已经停用
- 修改已保存凭据前须先关闭已启用任务；切换定时模式也先关闭再启用
- 安装器不启用定时任务；卸载保留个人配置。构建/CI 的验证范围与未完成的干净 Windows 10/11 验收见 [桌面版指南](windows-desktop.md)，不能据测试通过声称所有机器绝无误报

## macOS 手动预览

- 首次启动不读取 Keychain、不访问学校；账号操作需主动触发，不提供定时注册，`--scheduled` 返回失败
- 共享桌面服务保留正式锁、`SWUDK_PROBE_ONLY=1` 防护与提交前确认；Keychain 失败采用固定错误类别，不回退明文或输出系统错误文本
- 当前仅有原生 CI 与合成 Keychain/GUI/OCR 验证，交付为 ad-hoc 签名、未公证预览。Gatekeeper 和标准用户实机验收仍需单独完成；安全存储可用不等于公开分发已经获系统批准

## Android 手动预览

- 默认单账号、无自动登录或后台定时；仅申请 INTERNET 权限，不读取 GPS。学校宿舍坐标不能证明本人在寝
- 验证码图片来自共享核心同一登录 session；桥接层只接收图片 bytes，限制 1 MiB / 200 万像素，工作线程最多等待两分钟。答案为 3–16 位 ASCII 字母/数字，取消、过期答案、图片异常与超时停止该次登录，不回退 OCR
- 账号/验证码 Activity 设置 `FLAG_SECURE`；账号、密码和验证码不写入 Android saved instance state、截图证据或日志。旋转仅保留进程内状态，离开前台取消正在等待的操作
- 查询和只读诊断的实际提交入口被阻止；手动签到先查询 pending，再勾选本人在寝并确认。一次确认只授权一次服务层尝试，核心重新读取身份/请假/任务并以服务端回查确认成功
- 取消仅保证阻止尚未发出的提交；请求发出后不能撤销，取消后必须先重新查询服务端状态，不能因界面取消或连接失败连续提交
- 当前 0.1.1-preview 区分持久签名非调试 canonical 候选和 `.feasibility` 临时 debug 验证；私钥与 DPAPI 密码在仓库外受限当前用户目录，不公开、不传入 PR 工作流。已建立受限 ACL 的本机备份，并以恢复副本实际签名验证同一证书；离机保管和异机签名恢复未验证，公开 APK 前仍须完成；公开证书和实际 APK 指纹可核对
- 正式包与旧 debug 包可共存；密文的 AAD/包名和设备 Keystore 绑定，旧账号不自动复制，用户须在新包重输。同证书同版本覆盖的合成账号保持有独立测试，不能据此声明任意跨版本迁移通过
- 新包要求项目/运行库/依赖原文与逐文件哈希清单，发行构建拒绝脏源码，并校验内嵌来源、证书和 16 KB 对齐；这些检查不证明设备完整性、真实学校认证或商店批准。CI debug 不自动公开为 Android 资产，见 [发布准备](releases/release-readiness.md)
- 真机/模拟器学校业务使用合成数据；真实 SWU 登录/签到与 16 KB 实体设备仍未验证。历史 debug 与当前 release 结果分别记录，使用边界见 [Android 指南](android-client.md)

## 第三方与责任

这是非官方社区工具，学校接口随时可能变化。运行者负责保管凭据、选择部署环境并遵守学校规则。仅支持当前仓库的 `main` 和明确发布版本；降低上述安全边界的 fork 不在支持范围内。
